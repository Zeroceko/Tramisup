# Tiramisup Manifesto

## Core Claim

Tiramisup is not a classic SaaS dashboard with AI added on top.

Tiramisup is an AI-native execution workspace.

The product exists to turn a founder or builder's intent into structured action:

`conversation -> context -> decision -> action -> memory -> progress`

If a feature does not strengthen that chain, it is likely not a Tiramisup feature.

## What Tiramisup Is

- A workspace where the primary entry point is intent, not navigation.
- A product that turns answers into tasks, checklist items, routines, decisions, and next steps.
- A system that stays grounded in product stage, evidence, and current execution state.
- A calm operating layer for launch and growth work.

## What Tiramisup Is Not

- Not a generic chatbot inside a product shell.
- Not a dashboard that forces users to hunt through menus before they can act.
- Not a startup-advice generator full of generic tips.
- Not a chat experience that ends at text instead of operational change.

## Product Belief

Our users increasingly work by talking to software.

They already use tools like ChatGPT or Gemini to think, decide, draft, debug, and plan. Tiramisup should not fight that behavior. It should absorb it and make it operational.

The shift we believe in is this:

- old software: navigate -> inspect -> decide -> act
- Tiramisup: express intent -> receive grounded guidance -> convert to action -> review progress

Navigation still matters, but it becomes a support layer, not the center of the product.

## The Main Job

Tiramisup must help the user answer:

- What should I do right now?
- Why is that the right next step?
- Can you turn that into work for me?
- What changed since the last time I asked?

The best Tiramisup experiences do not stop at explanation. They end in structured execution.

## AI-Native Principles

### 1. Intent First

The product should prefer starting from what the user wants to accomplish, not from where they must click.

### 2. Action Over Output

A response is only half-complete until it can become a task, checklist item, routine, metric action, or decision artifact.

### 3. Context Before Cleverness

The system must be grounded in product stage, product context, evidence, tasks, checklists, metrics, and integrations before generating guidance.

### 4. Calm Over Hype

The experience should feel clear, operational, and trustworthy. Not loud, magical, or novelty-driven.

### 5. Memory Matters

Users should not need to restate core context every time. Tiramisup should remember the product, current state, previous guidance, and accepted or rejected actions.

### 6. Proof Over Generic Advice

Recommendations should be stage-aware, evidence-aware, and product-specific. Generic startup advice is a failure mode.

### 7. Menus Become Secondary

Classic surfaces like Dashboard, Growth, Metrics, and Settings still matter, but they exist to review, verify, and manage state. They are not the only way into the system.

## Experience Rules

- The default user journey should move from question to action.
- AI answers should explain the recommendation and make the next step operable.
- The system should prefer checkable task candidates over long text walls.
- The interface should reveal confidence, assumptions, or missing data when useful.
- The product should help users progress even when the answer is uncertain.

## Dashboard, Growth, Metrics, Settings

The existing product boundaries still matter.

- Dashboard asks: what is the next correct step right now?
- Growth asks: where is the weak link and what should we do next?
- Metrics asks: what do we measure, how does data arrive, and what changed?
- Settings manages product context, sources, tracking, security, and future AI connection controls.

AI-native does not mean collapsing every surface into one chat box. It means each surface becomes more intent-aware and more action-oriented.

## Execution Rule

When a user asks a question, the ideal Tiramisup response should do some combination of the following:

- answer clearly
- explain why now
- show supporting evidence
- propose task candidates
- let the user select and add them
- update the execution system

If the experience ends at text alone, we likely stopped too early.

## Team Rules

When building Tiramisup:

- Do not ship generic AI features detached from execution.
- Do not add chat merely for trend alignment.
- Do not design around menus first if intent can lead the flow better.
- Do not break stage-aware behavior in pursuit of a more impressive-looking AI surface.
- Do not let the product become a thin wrapper around a model.

Instead:

- build action surfaces
- preserve evidence-aware logic
- make AI outputs operational
- keep the user in control of what gets added or changed
- bias toward clarity, groundedness, and momentum

## Decision Filter

Before approving a feature, ask:

1. Does this reduce the distance between user intent and execution?
2. Does this make the product more context-aware, not more generic?
3. Does this create structured action, not just more text?
4. Does this preserve trust, clarity, and stage-appropriate guidance?
5. Would this still feel like Tiramisup if the chat UI disappeared?

If the answer to most of these is no, the feature is probably off-vision.

## Short Version

Tiramisup is not software with chat added.

Tiramisup is software that becomes an action surface through AI.
