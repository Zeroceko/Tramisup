# Persona Founder Simulation Plan

## Purpose

This plan is for realistic founder-style observation runs inside Tiramisup.
The goal is not only to find bugs. It is to learn:

- whether onboarding leads to value
- whether the launch/metrics/growth/tasks loop feels natural
- whether AI guidance is actually useful
- where trust breaks
- where users slow down, guess, or abandon

## Rules

- Do not explain the product while the session is running.
- Let the persona "drive" the product with minimal intervention.
- Record confusion, hesitation, dead ends, trust loss, and recovery moments.
- Prefer Turkish runs first because locale consistency is currently a live risk area.

## Persona Set

### 1. Defne Kaya — Pre-launch indie hacker

- Profile: solo builder, launch in 4-8 weeks
- Product type: lightweight SaaS
- Main need: launch clarity and checklist confidence
- Success question: does Tiramisup turn vague launch anxiety into concrete next steps?
- Key checks:
  - can create a product without confusion
  - sees a believable launch checklist
  - can convert one checklist item into a task
  - understands what "ready" means

### 2. Mert Arslan — Solo SaaS founder with early users

- Profile: live product, some real usage, no consistent operating rhythm
- Product type: B2B SaaS
- Main need: one clear next move
- Success question: does Tiramisup reduce decision fatigue?
- Key checks:
  - launched onboarding reaches the right post-onboarding surface
  - metrics/growth relationship is understandable
  - dashboard/agent guidance helps choose the next action

### 3. Selin Demir — Non-technical founder

- Profile: product owner, not technical, low tolerance for jargon
- Product type: operational tool for SMBs
- Main need: confidence and plain-language guidance
- Success question: does the product coach instead of intimidate?
- Key checks:
  - UI copy is understandable
  - settings, regenerate, and checklist language stay trustworthy
  - user can ask the AI for help without breaking flow

### 4. Emre Yılmaz — Growth-minded operator

- Profile: metrics-aware founder/operator
- Product type: live SaaS with a growth mandate
- Main need: data-led prioritization
- Success question: does Tiramisup feel specific rather than generic?
- Key checks:
  - metrics setup is credible
  - growth surface points to a usable action
  - AI/task suggestions do not feel shallow

### 5. Duru Çelik — Multi-product studio operator

- Profile: manages multiple bets at once
- Product type: studio / agency-like founder workflow
- Main need: portfolio clarity and context switching
- Success question: can one account actually manage multiple product contexts cleanly?
- Key checks:
  - products page feels organized
  - switching active product is reliable
  - portfolio view helps choose where to focus

## Standard Session Structure

1. Login with an existing test founder account
2. Create a new product matching the persona
3. Complete onboarding using the persona's context
4. Reach the next meaningful surface:
   - pre-launch persona -> launch workspace
   - launched personas -> growth / metrics / dashboard
5. Try one "progress" action:
   - create a task
   - mark something done
   - save metric setup
   - ask AI a concrete question
6. Capture friction notes and screenshots

## Shared Observation Fields

- First moment of hesitation
- First trust-building moment
- First trust-breaking moment
- Any locale mismatch
- Any performance pain
- Any unexpected dead end
- Whether the next step became clearer by the end
